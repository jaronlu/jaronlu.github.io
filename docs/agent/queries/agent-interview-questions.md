# Agent 面试高频问题

> confidence: medium

## 基础概念类

### Q1: 什么是 Agent？和传统 LLM 应用有什么区别？

**15 秒版本**：
> Agent 是使用 LLM 决定控制流的系统。传统 LLM 被动响应，Agent 主动规划、调用工具、动态决策。

**60 秒版本**：
> Agent = LLM（大脑）+ 工具（手脚）+ 记忆（状态）。区别在于：传统 LLM 应用是固定流程，Agent 能根据中间结果动态决定下一步。比如查天气，传统方式是写死调用天气 API，Agent 会判断用户意图后自主决定是否调用、调用哪个工具。

### Q2: 什么是 RAG？解决了什么问题？

**15 秒版本**：
> RAG 是检索增强生成，解决模型不知道私有知识、最新知识的问题。先检索相关文档，再让模型基于证据回答。

**60 秒版本**：
> RAG = Retrieval（检索）+ Augmented（增强）+ Generation（生成）。核心链路：文档切片 → 向量化 → 存入向量库 → 用户提问时检索相关片段 → 拼入 Prompt → LLM 生成回答。解决三个问题：私有知识问答、知识时效性、降低幻觉。

### Q3: LangChain 和 LangGraph 有什么区别？

**15 秒版本**：
> LangChain 是高层 Agent 应用框架，快速搭建；LangGraph 是低层有状态编排，精确控制。

**60 秒版本**：
> LangChain 提供模型、工具、消息等通用抽象，适合快速原型。LangGraph 提供图结构编排，支持循环、分支、暂停恢复、人工审核，适合复杂长流程。两者常搭配使用，LangChain 做高层抽象，LangGraph 做底层控制。

## 技术实现类

### Q4: Agent 的执行循环是怎样的？

```
接收任务 → 理解目标 → 判断是否调用工具 → 执行工具 → 读取结果 → 决定下一步 → 输出答案
```

关键点：
- 每一步都可能调用 LLM 做决策
- 工具调用结果会影响下一步决策
- 需要终止条件防止死循环

### Q5: 什么是 MCP？解决了什么问题？

**15 秒版本**：
> MCP 是 Model Context Protocol，AI 世界的 USB 接口。让外部服务标准化提供工具，AI 应用无需重复定义。

**60 秒版本**：
> MCP 解决两个问题：1）不同 Agent 重复定义相同工具；2）全世界服务接口各异，对接麻烦。MCP Server 提供标准工具，MCP Client 连接使用，MCP Host 协调管理。通信方式有 stdio（进程通信）和 SSE（HTTP 流）。

### Q6: 多 Agent 协作有哪些模式？

| 模式 | 特点 | 适用场景 |
|------|------|----------|
| Subagents | 主 Agent 协调子 Agent | 任务可拆分、需并行 |
| Handoffs | 状态转移触发切换 | 需要用户交互、多跳执行 |
| Skills | 单 Agent 动态加载能力 | 能力按需组合 |
| Router | 请求分类导向专门 Agent | 请求类型明确、需并行 |

### Q7: RAG 的核心优化点有哪些？

1. **文档清洗**：源数据质量决定上限
2. **Chunk 粒度**：太大太小都不好
3. **检索策略**：向量/BM25/Hybrid
4. **Rerank**：重排提升相关性
5. **上下文控制**：长度限制、信息密度
6. **回答护栏**：防止幻觉、确保基于证据

## 工程实践类

### Q8: Agent 的核心风险有哪些？

| 风险 | 说明 | 应对 |
|------|------|------|
| 幻觉决策 | LLM 编造工具或结果 | 工具白名单、结果校验 |
| 工具乱调 | 调用错误工具或传错参数 | 参数校验、错误处理 |
| 死循环 | 无法终止的推理循环 | 步数限制、超时机制 |
| 成本失控 | 多轮调用 token 消耗大 | 成本监控、缓存策略 |

### Q9: 如何评估 RAG 系统效果？

关键指标：
- **召回率**：相关文档是否被召回
- **精确率**：召回的文档是否相关
- **延迟**：检索+生成的总时间
- **Token 成本**：每次调用的 token 消耗
- **回答质量**：是否基于证据、是否准确

### Q10: 你会如何设计一个 Agent 系统？

**2 分钟版本**：

1. **明确目标**：单任务还是多任务？开放还是封闭？
2. **选择架构**：
   - 简单任务：LangChain + 单 Agent
   - 复杂流程：LangGraph + 状态机
   - 知识问答：RAG 系统
3. **设计工具**：最小化工具集，先跑通核心链路
4. **状态管理**：State（短期）+ Store（长期）
5. **错误处理**：超时、重试、降级、成本控制
6. **评估迭代**：追踪、评测、优化

我在 [SecRAG](../../projects/secrag.md) 里的实际做法：把这套设计拆成 Planner→Retriever→Reasoner→Verifier→Composer→Auditor 六个可审计节点，用 LangGraph StateGraph 编排条件路由（检索不足时回退到 Planner 重新规划），而不是一次 Prompt 全包。

## 行业认知类

### Q11: 客户端工程师转 Agent 开发有什么优势？

优势：
- 工程化思维：状态管理、错误处理、性能优化
- 系统设计能力：模块化、可扩展、可维护
- 用户体验意识：交互设计、边界处理
- 调试能力：复杂系统排障经验

垂直行业背景（如证券金融）会进一步放大这个优势——知道"投顾能看什么、合规要查什么、数字错了后果是什么"，能直接转化为 Agent 系统里的权限设计和验证逻辑，而不是纯技术侧的架构练习。
