    AI Agent 学习路径¶

    confidence: medium

    这是一条面向求职投递的 AI Agent 学习路线。它不追求一次性学完所有 AI 技术，而是按"能投递、能解释、能做项目"的顺序推进。

    岗位画像¶

    AI Agent 岗位不再只看"会调大模型 API"。高频要求已经收敛到四件事：能做 Agent 运行时，能做 RAG / 知识工程，能把系统部署到生产环境，能用评测和观测证明效果。

    类型 典型岗位 准备重点
    社招开发岗 AI 智能体开发、Java Agent、Agent 前端开发 工程架构、服务端能力、业务闭环、稳定性
    社招算法岗 长程 Agent、多模态、RL、大模型算法 PyTorch / Hugging Face、SFT / RLHF、评测
    实习开发岗 大模型 Agent 开发、AI 应用研发 可演示项目、RAG、工具调用、部署
    产品岗 AI Agent 产品经理、AI 应用产品 场景抽象、指标体系、Prompt / 知识库理解

    从 JD 反推，学习优先级不是"框架越多越好"，而是：

    1. Agent 运行时能力：任务规划、工具调用、记忆管理、多 Agent 协同、失败恢复。
    2. RAG 工程能力：数据管道、向量库、混合检索、引用标注、召回评估。
    3. 工程化能力：API 服务、权限、日志、监控、缓存、成本控制、部署。
    4. 业务建模能力：把 Agent 放进电商、金融、安全、企业知识库等真实流程。
    5. 评测能力：离线评测集、人工验收、trace 复盘、迭代指标。

    简历表达要把"用了什么工具"改成"系统怎么闭环"：状态机、工具协议、失败重试、知识库检索评估、引用验证、部署监控和业务指标。

    总原则¶

    • 先做出能演示的最小项目，再补理论深度。
    • 每个阶段都要有验收物：代码、笔记、Demo、评测结果或面试表达。
    • 阶段 9 必须落到作品，例如能说明需求、架构、检索、Agent Graph 和引用验证的项目（这条路径对应我自己在做的 SecRAG）。

    路径总览¶

    阶段 主题 预估时间 核心产出
    0 工程基础补缺 1-2 周 Python / Git / HTTP / SQL 小练习
    1 Python 数据与模型生态 2 周 Pandas 数据处理 + PyTorch 小模型
    2 LLM 核心原理 2 周 Transformer / Attention / Token 面试解释
    3 Prompt Engineering 1 周 3 套可复用 Prompt 模板和效果对比
    4 RAG 与知识工程 2 周 可上传文档的 RAG 问答系统
    5 Agent 开发框架 2 周 带工具调用和状态管理的 Agent
    6 微调与对齐 2 周 小模型 LoRA 微调实验记录
    7 推理优化与部署 1 周 FastAPI / Docker / 流式输出服务
    8 评测与可观测性 1 周 RAG / Agent 的评测和 trace 面板
    9 综合项目实战 2-3 周 可演示、可复盘、可写进简历的项目

    阶段 0：工程基础补缺¶

    目标是避免 AI 项目做成脚本玩具。至少补齐 Python、Git、HTTP、SQL、Linux 基本操作、常见数据结构和网络请求链路。

    验收标准：

    • 能独立写一个 CLI 或 FastAPI 小服务。
    • 能解释一次 HTTP 请求从客户端到服务端的基本链路。
    • 能用 SQL 做查询、过滤、聚合和简单索引解释。

    阶段 1：Python 数据与模型生态¶

    重点不是刷语法，而是形成 AI 工程最常用的处理能力：数据清洗、向量化、张量计算、训练循环和文件管道。

    验收标准：

    • 能用 Pandas 处理 10 万行级别 CSV，并输出清洗报告。
    • 能用 PyTorch 写一个最小分类模型，说明训练、验证、损失和指标。
    • 能把数据处理逻辑拆成可复用函数，而不是一次性 notebook。

    阶段 2：LLM 核心原理¶

    求职不需要手写完整大模型，但要能把关键概念讲清：Transformer、Self-Attention、Tokenization、上下文窗口、采样策略和幻觉来源。

    验收标准：

    • 能白板解释 Self-Attention 的输入、权重和输出。
    • 能说明 Temperature、Top-p、上下文窗口对生成结果的影响。
    • 能区分"模型能力问题"和"检索/上下文/提示词问题"。

    阶段 3：Prompt Engineering¶

    Prompt 不是玄学文案，而是任务约束、上下文组织和输出结构控制。这里要练 Zero-shot、Few-shot、CoT、ReAct、结构化输出和 Judge 评估。

    验收标准：

    • 同一任务能写出 3 种 prompt 策略，并比较效果。
    • 能把 prompt 拆成 system / context / instruction / output schema。
    • 能说明 prompt 版本如何管理和回归测试。

    阶段 4：RAG 与知识工程¶

    这是 AI Agent 岗位最实用的基础能力。重点掌握文档加载、chunk、embedding、向量库、混合检索、重排、引用标注和离线评测。

    验收标准：

    • 能搭建一个 PDF / Markdown 知识库问答系统。
    • 能解释 chunk size、overlap、embedding 模型和 top-k 的取舍。
    • 能输出引用来源，并能用测试集评估命中率和答案质量。

    阶段 5：Agent 开发框架¶

    进入 Agent 后，核心是把"模型回答"变成"可控执行循环"。需要掌握任务规划、工具调用、状态管理、记忆、失败重试和多 Agent 协作。

    优先顺序：

    1. 先理解 Agent 原理。
    2. 再用 LangChain / LangGraph 做单 Agent 工具调用。
    3. 最后再做多 Agent、长期记忆和人工审核节点。

    验收标准：

    • 能实现一个 Thought -> Action -> Observation 循环。
    • 能给 Agent 增加搜索、数据库或本地文件工具。
    • 能保存状态，并在失败后重试或降级。

    阶段 6：微调与对齐¶

    这部分不是所有开发岗都必需，但算法岗和高阶 Agent 岗会看。重点理解 SFT、LoRA / QLoRA、DPO、RLHF、数据集构建和评估。

    验收标准：

    • 能用 LoRA 微调一个小模型，并记录数据集、参数、训练成本和效果对比。
    • 能解释微调、RAG、Prompt 三种方案分别适合什么问题。
    • 能说明对齐数据质量比盲目堆训练更重要。

    阶段 7：推理优化与部署¶

    目标是把模型能力变成可访问服务。重点是 FastAPI、SSE 流式输出、Docker、vLLM / llama.cpp、并发控制、缓存和成本估算。

    验收标准：

    • 能把一个 RAG 或 Agent 封装成 API。
    • 能用 Docker 启动服务，并写清启动参数。
    • 能解释吞吐、延迟、上下文长度和成本之间的取舍。

    阶段 8：评测与可观测性¶

    生产级 Agent 必须可追踪。要能记录输入、检索结果、工具调用、模型输出、延迟、token 消耗、错误和人工反馈。

    验收标准：

    • 能为 RAG 系统建立一组固定测试问题。
    • 能输出请求 trace，定位错误来自检索、工具、prompt 还是模型。
    • 能用指标说明一次优化是否真的有效。

    阶段 9：综合项目实战¶

    最终至少准备一个主项目，不要分散做很多半成品。项目应覆盖需求、数据、RAG、Agent、API、评测、部署和复盘。

    推荐项目方向：

    项目 覆盖能力 简历表达
    企业级 RAG 问答系统 文档处理、向量检索、引用验证、评测 能证明知识工程和可靠回答能力
    多 Agent 协作系统 规划、工具、状态、人工审核 能证明 Agent 运行时设计能力
    领域模型微调 + 部署 数据集、LoRA、评估、推理服务 能证明算法和部署理解
    AI Coding Agent 工具调用、代码生成、MCP、任务分解 能证明 Agent 工程化和开发效率

    展示材料：

    • README：问题、方案、架构、运行方式、效果。
    • Demo：5 分钟以内，展示主流程和失败处理。
    • 复盘：指标、局限、下一步优化。
    • 面试话术：为什么这么设计，有哪些替代方案，如何上线。
